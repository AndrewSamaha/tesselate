# F11: Real-session end-to-end demonstration

**Owner:** integration/test agent. **Depends on:** a thin session can start after F00; full acceptance needs F03–F10. **Output:** reproducible acceptance scenarios using real MCP connections and local Git repositories.

## Scope

- Build fixtures with two temporary local repositories and a harness that connects supervisor, coding, and review roles through stdio MCP adapters. The harness may start agent processes; Tesselate does not host models.
- Grow the scenario incrementally: connect and discover; create/assign a task; create worktrees and submit commits; review and revise; export and inspect history.
- Exercise at least two coding sessions concurrently in separate worktrees and at least two non-author review sessions. Include a concrete finding or explicit pass from each reviewer, a routed revision, and a new review round.
- Restart the coordinator mid-run and verify assignments, messages, Git references, pending reviews, and cursors remain usable.
- Complete one run autonomously; stop a separate run at a configured limit and verify its terminal reason and remaining work.
- In a separate configuration, pause a governed transition for a human request, resolve it through the CLI, and continue.
- Verify JSON Lines and Markdown can reconstruct the run without the service; verify ordinary cleanup refuses a dirty worktree.

## Acceptance

- Automated or scripted checks cover all nine criteria in spec §11 through real MCP sessions, rather than direct core calls.
- The scenario records commands, fixture setup, expected assertions, and observed results so another agent can reproduce it.
- Failures identify the feature boundary responsible; the demonstration does not silently skip unavailable components.

**Boundary:** no primary-branch merge is required. The final report identifies reviewed commits and remaining integration steps.
