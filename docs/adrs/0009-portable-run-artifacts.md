# ADR-0009: Portable run artifacts

Status: Accepted for M001

F10 exports a run snapshot under the F01 artifact directory using stable names: `events.v1.jsonl`, `records.v1.jsonl`, and `timeline.v1.md`. The event log is paged from F02 in ascending immutable sequence. A second versioned JSONL carries current run-scoped durable records that events reference but intentionally do not duplicate, such as message bodies and persisted review findings. The Markdown timeline links those identifiers and includes the related records so readers do not need SQLite or a running coordinator.

The exporter reads only the scoped event and entity APIs. It does not add events or change workflow state. Its three paths are deterministic. Each file is written to a temporary sibling, synced, and renamed into place. On Unix, rerunning atomically replaces each prior file from the current persisted snapshot. On non-Unix systems, creation at a new path works, but an existing destination is preserved and replacement returns an error if the platform rename cannot replace it; repeat export after a completed export is therefore not promised there.

Credential issuance event types are omitted. Fields whose keys name secrets, credentials, passwords, tokens, verifiers, authorization data, API keys, private keys, or machine-local filesystem paths are recursively omitted from event and related-record payloads. Producers must keep credentials, secret configuration, and complete repository file contents out of persistent history. Markdown escapes all untrusted text and creates local links only for validated UUIDs and hexadecimal commit IDs. F09 invokes export; F08 owns authorization and discovery through the existing artifact-location contract.

For replacement, the writer preserves an existing artifact through a same-directory hard-link backup until the new file and its directory entry are synced. If the first directory sync fails, Unix restores the old artifact with one atomic `rename(backup, destination)` that replaces the new path directly; it never removes the public path before restoration. Once the new artifact is synced, backup cleanup is best-effort; a crash can leave a hidden `.bak` file, while the public artifact remains valid. Unix builds sync the parent directory through an open directory descriptor; this was exercised on the Linux development host. Non-Unix builds skip directory syncing, so the library does not promise equivalent power-loss durability there. On a platform where rename cannot replace an existing destination (including Windows), the exporter refuses that replacement and leaves the previous file intact. The MVP service is Unix-socket based; no Windows durability test is claimed.
