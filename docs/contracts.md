# F00 shared contracts

This crate defines transport-neutral API types in `core` and a `Coordination` trait. MCP and CLI adapters authenticate a bearer credential through `SessionAuthenticator`, then pass the resulting opaque `SessionContext`; it has private fields and no wire serialization, so client-supplied actor or role fields cannot construct authority. The coordinator checks the bound session and revocation state for each operation. Mutations persist state, event, and idempotency record through `persistence::Database::commit_mutation` in one immediate SQLite transaction. Reusing a key within `(session_id, operation, key)` with the same canonical request returns the original result/event and `replayed=true`; a different request is `IdempotencyConflict`. State preconditions are checked in the same transaction as the state, event, and idempotency write. Coordination owns authorization and transition policy; persistence owns durable atomicity.

F02 exposes a nonempty batch of typed-at-the-boundary `StateChange` records with insert or expected-revision update semantics, `Database::load` and bounded `list_entities` reads, scoped `events_after` timelines, and typed `messages_after` reads. Omitted task dependency replacement preserves existing dependencies; `Some(vec![])` explicitly clears them. Each nonempty event/message/entity page returns a persisted opaque cursor at its last item, even when there is no next page, so clients can resume before later records arrive. Cursor tokens resolve to durable event sequence positions and arbitrary cursor values are rejected.

Run creation includes a goal. A created `Run` stores its UTC start time and a snapshot of validated project `WorkflowLimits` (duration, concurrent assignment, task retry, and review round caps). Terminal runs may include a `RunOutcome` reason and remaining task IDs. A `Task` stores its goal, attempt count, submitted commit IDs, and optional result. The run limits come from project configuration and cannot be supplied by a task creation request.

Events use schema version 1, a monotonically increasing per-database `sequence`, UUID event identity, UTC timestamp, actor identity and role, optional project/run/task scope, stable snake-case event type, and structured JSON payload. Pagination is bounded and cursors are opaque, exclusive, sequence-backed tokens: a cursor after sequence N yields events with sequence greater than N in ascending order. Unknown or tampered cursors are errors. MCP uses namespace `tesselate.v1`, schema version 1, `ReadRequest` for reads, `MutationRequest` with a required idempotency key for mutations, and `ToolResponse` with explicitly tagged `{outcome:{status:"success"|"error",data:...}}`; error data is `{code,message,retryable}`. Unsupported schema versions return `unsupported_version`. The initial exact tool names are exported as `mcp::TOOLS`. Request `params` are tool-specific JSON; authenticated context is derived by the adapter and never accepted from those params. `Coordination` includes stable project/repository/agent/run/task discovery, run/task lifecycle and dispositions, available work, messages, workspaces, review rounds/findings, human decisions, timelines, and artifact lookup. Repository and agent lists are scoped to a project and use the standard bounded `PageRequest`/`Page<T>` cursor contract.

`CompleteRun` contains only the run ID and outstanding integration steps. The completion operation derives `Run.reviewed_commit_ids` from persisted task submissions whose commits have policy-satisfying persisted reviews. The caller cannot supply or override this list; completion fails if the review policy is not met. Final task dispositions are separately recorded with actor, reason, and event. Artifact lookup returns persisted export references and does not render artifacts.

Credential bootstrap, Git crash recovery, and completion semantics are decided in ADR-0001 through ADR-0003. F01–F11 should implement against these contracts. This is interface scaffolding; feature behavior remains with its feature owner.

F04 task transitions are authorized by `coordination::tasks::TaskEngine`. Assignment capacity is computed across all active tasks in the run. Reassignment after an expired F05 lease preserves prior assignment history and never removes F03 workspaces. Task dependencies unblock in the same persisted mutation that completes their prerequisite. Run duration and retry exhaustion persist a stopped run with its reason and remaining task IDs. Idempotency replay is resolved before state-dependent policy checks and rechecked after optimistic revision conflicts; the F02 commit transaction remains authoritative under races. See ADR-0005.
