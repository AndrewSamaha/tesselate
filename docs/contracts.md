# F00 shared contracts

This crate defines transport-neutral API types in `core` and a `Coordination` trait. MCP and CLI adapters authenticate a bearer credential through `SessionAuthenticator`, then pass the resulting opaque `SessionContext`; it has private fields and no wire serialization, so client-supplied actor or role fields cannot construct authority. The coordinator checks the bound session and revocation state for each operation. Operations that mutate state take an idempotency key and return the canonical result plus the event ID. Reusing a key within `(session_id, operation, key)` with the same canonical request returns the original result/event and `replayed=true`; a different request is `IdempotencyConflict`. The persistence implementation must write state, event, and idempotency result atomically.

Events use schema version 1, a monotonically increasing per-database `sequence`, UUID event identity, UTC timestamp, actor identity and role, optional project/run/task scope, stable snake-case event type, and structured JSON payload. Pagination is bounded and cursors are opaque, exclusive, sequence-backed tokens: a cursor after sequence N yields events with sequence greater than N in ascending order. Unknown or tampered cursors are errors. MCP uses namespace `tesselate.v1`, schema version 1, `ReadRequest` for reads, `MutationRequest` with a required idempotency key for mutations, and `ToolResponse` with explicitly tagged `{outcome:{status:"success"|"error",data:...}}`; error data is `{code,message,retryable}`. Unsupported schema versions return `unsupported_version`. The initial exact tool names are exported as `mcp::TOOLS`. Request `params` are tool-specific JSON; authenticated context is derived by the adapter and never accepted from those params. `Coordination` includes stable operations for run/task lifecycle, available work, messages, workspaces, review rounds/findings, human decisions and timelines. The core API and data types do not depend on MCP.

Credential bootstrap, Git crash recovery, and completion semantics are decided in ADR-0001 through ADR-0003. F01–F11 should implement against these contracts. This is interface scaffolding; feature behavior remains with its feature owner.
